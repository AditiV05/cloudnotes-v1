CloudNotes: Security Posture Summary

Tiered network · least privilege · default-deny · verified with connectivity tests (7/7 passed)

✔ Allowed traffic

  • Public → web tier (nginx) on tcp:80 (443 once TLS is added)
  • Web → app on tcp:5000
  • App → database on tcp:5432
  • App → internet (egress for updates)

✘ Denied traffic

  • Public → app :5000 and public → database :5432
  • Web → database (no shared network)
  • Database → internet (internal network)
  • Unused HTTP methods (PUT/PATCH → 405) and every unpublished port (default-deny)

🛡 How the database is protected

  • Publishes no port and has no external IP or route
  • Only the app tier shares its data network
  • Even a compromised web server can't resolve it (bad address 'db')
  • Password in .env, never in git

🔒 How admin access is controlled

  • No container runs SSH; port 22 is never published
  • Admin = docker compose exec on the host (requires login)
  • /health answers only local/private addresses
  • VM: ufw allow from <trusted-ip> to any port 22 · GCP: IAP only
Cloud translation: tiers → web/app/db subnets in a custom VPC; network membership → network tags / service accounts; published port → VPC ingress ALLOW rule; default-deny → implied deny-all-ingress; db subnet gets no external IPs and no Cloud NAT.
Least privilege: each tier gets exactly one inbound port from exactly one source, and the design is proven by testing that the dangerous paths are blocked.
